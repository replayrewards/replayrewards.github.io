How it works

Point GetInsightful at a source. It runs the actual Airbyte connector — real extraction, real loads — into your local Postgres warehouse.

2

Everything that lands is parsed into entities and indexed for hybrid search. Memories from every conversation join the store after you approve them.

Agents, first-class

Speaks MCP natively.

Every GetInsightful instance exposes an MCP server. Point Claude Desktop, Cursor, or any MCP client at it and your agents query the warehouse and search the same context your team does — approved memories included.

  • context_search — hybrid search over entities and memories
  • run_sql — read-only SELECTs against the warehouse
  • list_tables — schema discovery for planning
POST http://localhost:3000/mcp tools: context_search, run_sql, list_tables → "Why did claims-engine latency breach p95 three times this month?" ← grounded answer · entity: ClaimsEngine memory: "p95 SLA is 150ms for patient-api"
Local-first, on purpose

Your data. Your keys. Your machine.

The warehouse is a Postgres you own — one docker compose up. Nothing leaves your machine except the prompts you route to the model provider you configure. Bring your own key: Anthropic, or any Anthropic-protocol endpoint including Z.ai GLM.

FAQ

Fair questions.

Is the data real, or a demo simulation?
Real. GetInsightful executes genuine Airbyte connectors (via PyAirbyte) against your sources and lands typed tables in the warehouse. The bundled Genzeon engineering tenant is a sample dataset — the pipelines moving it are not mocked.
Where does my data live?
In a Postgres database you run locally (docker compose ships in the repo). Dashboards, chat history, entities, and memories are rows in your database. Only LLM requests leave the machine, and they go to whichever provider you configure.
Which AI models does it support?
Anything speaking the Anthropic protocol. There are first-class presets for Anthropic and for Z.ai's GLM endpoint, and you can point it at any compatible base URL with a key.
Can my existing agents and tools use it?
Yes — every instance exposes an MCP server at POST :3000/mcp with context_search, run_sql (read-only), and list_tables. Claude Desktop and Cursor work out of the box; there's also a REST API and an agent guide for authoring dashboards programmatically.
What's the stack?
Tauri 2 desktop app with an embedded axum server, sqlx over Postgres, React 19 front end, PyAirbyte for connector runs. The whole thing cold-starts from one script: ./run.sh.
